# CSRA reviewer audit package

Start with `CSRA_Independent_Audit.md`.

Updated after recovery of the execution, preactivation and factual-review materials: the lock-hash discrepancy is explained by two distinct documents; exact prompts, ten fictional controls and the sealed 240-row review are verified. The frozen selection rule reproduces the released final 100-item CSV byte for byte. Statistical results are unchanged.

`audit_csra.py` independently reconstructs and analyses the released v0.8 score summaries. It needs the extracted CSRA-8000 repository and the pinned packages in `requirements.txt`. It does not download or run language models.

```bash
python -m pip install -r requirements.txt
python audit_csra.py --repo /path/to/extracted/CSRA-8000 --out results --reps 2000
```

The original repository's own `python run_reproduction.py` was also run successfully in the pinned environment. Its default checks reproduce the principal point estimates and specified sensitivity/diagnostic summaries; the independent audit reproduces all five original alignment bootstrap intervals and the primary predictive interval.

Important outputs:

- `results/predictive_point_estimates.csv`: held-out R-squared and report increments with/without the recorded-answer predictor.
- `results/predictive_intervals.csv`: 2,000-draw full-refit paired bootstrap intervals and practical classifications.
- `results/alignment_scale_comparison.csv` and `results/alignment_intervals.csv`: original versus within-frame scaling.
- `results/conditional_alignment.csv`: separate model-specific conditional paired regressions; p-values are raw exploratory values.
- `results/per_frame_adjusted_slopes.csv`: original mixed-model PEER and SELF slopes.
- `results/report_role_distributions.csv`: all four report categories, by model/frame/condition.
- `results/fictional_controls_by_frame.csv`: unpooled fictional-control diagnostics.
- `results/implementation_validation.json`: comparisons with the released implementation and sealed expected results.
- `results/audit_summary.json`: method, environment, integrity checks, and limitations.
- `results/model_history_comparison.csv`: same-revision comparison additionally using the earlier v0.6 upload; not regenerated by the main command.
- `results/lock_lineage_verification.json`: recovered metadata/canonical lock distinction, checksum checks, and deterministic fold verification.
- `recovered_provenance/`: exact recovered lock, completion, seal, and companion files.
- `results/preactivation_asset_verification.json`: prompt/control execution commitments and all 14 Step-2 component checks.
- `recovered_prompts_example.md`: a report example reconstructed from the recovered templates and released summaries.
- `results/factual_review_verification.json`: all 19 checks on review versions, recorded counts, reasons and byte-identical final-item selection.
- `recovered_provenance/factual_review/`: all four uploaded review CSVs, preserved unchanged.

After running the statistical audit, reproduce the new lock check using:

```bash
python audit_lock_lineage.py --package /path/to/CSRA_v08_ANSWER_EXECUTION_R4_A2_TR2_PACKAGE.zip --repo /path/to/extracted/CSRA-8000 --out results/lock_lineage_verification.json
python audit_preactivation_assets.py --package /path/to/CSRA_v08_PREACTIVATION_COMPLETE_PACKAGE.zip --out results/preactivation_asset_verification.json
python audit_factual_review.py --reviews recovered_provenance/factual_review --repo /path/to/extracted/CSRA-8000 --records recovered_provenance --out results/factual_review_verification.json
```

All new analyses are exploratory and follow peer review. The package verifies statistical calculations from released summaries and supplied review/selection records. It does not independently establish factual correctness of the review decisions, the original language-model scoring, reviewer identity or prospectively locked timing. Input archive and review-CSV hashes are recorded in `input_archives.json`; the original ZIPs are not duplicated here.
