# Existing-item exploratory pilot: amendment of 19 October 2026

The pilot proceeds without external registration. This is a change in workflow and evidential status, not in the four planned contrasts or their numerical methods. The original registration gate is replaced by an explicit exploratory execution mode and an internal source snapshot created before new reports in that run folder. The earlier draft registration documents remain historical proposals; no fictitious registry entry or retroactive registration is created.

## Scope retained

- Existing 100 selected items, 57 ordered P/C/I triples; original frozen answer summaries.
- Three fixed development systems at the original locked model/tokenizer revisions, NF4/double-quantized weights and FP32 computation. OWN remains wording in a stateless fresh conversation.
- Eight ownership x hedging x recorded-answer-visibility cells; three C-document strengths and four role-label rotations: 28,800 logical jobs, 9,600 per system.
- P1 q_both OWN-OTHER; P2 hedged-certain; P3 shown-hidden; P4 equal-system/hedging mean shown-hidden difference in incremental OWN predictive R2 after OTHER, with the answer omitted from the primary baseline.
- Original exact prompts, label IDs, log-score aggregation, three-ALR primary representation, Ridge alpha=1, fixed five whole-triple folds, 10,000 relation-stratified paired cluster bootstrap draws, seed 20261016, and four 98.75% percentile intervals.
- Same technical retry, joint complete-case exclusion, no replacement, no interim significance stopping, and secondary analysis settings. Analyze only after all jobs have a committed status. More than 5% attrition flags incomplete evaluation.

Here "primary" identifies the planned main analysis of an exploratory pilot. It does not mean untouched confirmatory evidence. An adjusted interval can quantify an estimated contrast without establishing model-family generality or privileged self-access. Existing Study 1 outcomes were already known. This change cannot repair historical item-review or provenance gaps.

## Simpler sequence

1. Validate the new source package; install exact dependencies after removing unused incompatible torchvision/torchaudio; perform early import and GPU checks.
2. Run synthetic technical preflight for all three models, without inspecting real pilot outcomes.
3. Run the freeze command. It copies every locked source/input/protocol file into the durable run folder and records a local timestamp/hash. This is an internal record, not an independent timestamp.
4. Collect/resume all three models with --mode exploratory. No registration JSON is required.
5. Analyze the complete set and retain analysis_status.json, checkpoints, failures, frozen sources and a downloaded backup. Report the internally frozen, existing-item exploratory status honestly.

The package does not launch models, collect reports or register anything during local preparation. Any fresh-item study requires a separately settled design and resource decision. External preregistration can be considered then; it is not a prerequisite to using this pilot for feasibility and precision assessment.
