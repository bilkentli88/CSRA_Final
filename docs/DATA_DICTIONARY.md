# Data and scoring dictionary

## Original released summaries

`original_release/data/final_common_items.csv`: the deterministic selected 100 items, including question, subject, relation and P/C/I answer strings. P is the designated factual/parametric answer, C the document counterfactual, I the distractor. The original screening made P the no-document modal answer; this is not imposed on Fresh40.

`data/supporting/*_answer_condition_summary.csv`: model/condition summaries averaged over six answer-label permutations. The outcome CIE is the C-minus-P log-support contrast under a C-asserting document minus that under the matched P-asserting document.

`*_main_report_results.csv`: four role log supports averaged over four cyclic label orderings, with SELF/PEER frames. Scalar VSA is document minus prior log support. Modal answers/reports use the maximum averaged log support, not unconstrained natural-language generation.

`original_reanalysis/audit/results/reconstructed_primary_units.csv`: 900 model/item/strength rows used by the reanalysis. `original_reanalysis/results/` retains the V1 orthonormal representation and revised bootstrap outputs.

## Later score ledgers

Factorial `*_checkpoint.jsonl` and development/Fresh40 `scores/*.jsonl` contain committed batches. A line contains batch runtime/provenance and a `rows` list. **A JSONL line is a batch, not one scientific observation.** Each row has a job ID, prompt hash, A/B/C/D label log supports, batch size and retry records. Label-to-role mappings are regenerated by the frozen job generators; compare prompt hashes before interpreting a row.

The factorial run has 9,600 report jobs per model, 28,800 total; 7,200 aggregated model/item/strength/cell rows. Cells cross OWN/OTHER ownership, certain/hedged wording, and shown/hidden recorded answers. `q_*` is normalized support over four labels, not calibrated attribution probability.

FP32 development has 4,800 answer jobs per target and 7,200 report jobs per reporter: 43,200 total. `analysis_inputs.json` contains 900 cases. Its held-out error rows contain averages across ordered reporter pairs, cues and slot permutations as defined by the common decoder. A single native/external squared-error field is not necessarily the error of one single displayed report pair.

Fresh40 has 1,920 answer jobs per target and 2,880 report jobs per reporter: 17,280 total. `analysis/fresh_analysis_inputs.json` contains 360 cases. `per_case_predictions.csv` contains 720 rows: each case is evaluated by gradient boosting and Ridge.

## Fresh40 policy columns

| Policy | Information added to visible relation/strength and nested text forecasts |
|---|---|
| `visible` | None |
| `self` | Same-target model's three averaged report ALRs |
| `observer` | Three report ALRs from an external reporter selected on old100 |
| `probe` | Three P/I-invariant functions of no-document target supports |
| `probe_self` | Direct probe plus same-target report ALRs |
| `probe_observer` | Direct probe plus selected external report ALRs |
| `reference_ceiling` | Reference-aware role/margin features; a reference-aware diagnostic, not a mathematical performance ceiling or an available public-input policy |

`Y` is the target's CIE in natural-log units. `<policy>_prediction` predicts Y; `<policy>_squared_error` is its squared error. Positive `(baseline_error - new_error) / old100_Y_variance` favors the new policy. Average across the 40 whole groups, each with all three strengths and targets. Individual-target fresh R² uses fresh outcome variance and is a different quantity.

Model/encoder repository revisions, exact templates, token audits, grouping rules and feature construction are retained in each frozen package's protocol and code. Raw scores are label log supports, not token-by-token internal activations or causal traces.
